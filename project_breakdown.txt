# PART 1: The Project, In Full

## 1.1 What we're building

We are reproducing a research paper: **"Fine-Grained DINO Tuning with Dual Supervision for Face Forgery Detection"** (arXiv:2511.12107v1, Nov 2025). The paper builds a deepfake (face forgery) detector by attaching a custom lightweight adapter — the **DFF-Adapter** — to a frozen, pretrained vision model called **DINOv2**. We are also adding one small original contribution: testing whether "softening" part of the training signal fixes a limitation the paper's own authors admit to.

## 1.2 Why this problem matters (plain language)

Deepfakes are AI-generated or AI-manipulated face images/videos realistic enough to fool people. Detecting them automatically is an important security problem. The core difficulty: a detector trained on today's fake-generation techniques must still catch tomorrow's new techniques it has never seen — this is called **generalization**, and it's the hardest part of the whole field.

## 1.3 The core idea of the paper, explained from first principles

**Step A — Start with a pretrained "eye."**
Instead of training a neural network from scratch, we start with **DINOv2**, a Vision Transformer (ViT) that Meta AI pretrained on millions of general images (not faces specifically) using self-supervised learning. It already has a very refined sense of textures, shapes, and structure. We **freeze** it — meaning during our training, none of DINOv2's own weights change. This saves compute and avoids "forgetting" its general knowledge.

**Step B — Attach small trainable "adapters" instead of retraining everything.**
Fully retraining DINOv2 would be too expensive and prone to overfitting on our smaller dataset. So we attach small trainable modules called **LoRA (Low-Rank Adaptation)** at specific points inside DINOv2, and only train those. LoRA works by adding a small learned "correction" to certain weight matrices, computed as the product of two small matrices (A and B) instead of one huge matrix — this means very few parameters need training.

**Step C — Insert adapters at EVERY layer, not just the last one (this is the paper's first key idea).**
Most prior work only adapts the final transformer block of DINOv2. This paper's insight: important forgery clues live in low-level texture patterns detected in **early** layers, not just high-level semantic patterns in **late** layers. So DFF-Adapter inserts a LoRA-based module into the query, value, and dense projection of **every single transformer block**.

**Step D — Train on TWO tasks at once, not just one (this is the paper's second key idea).**
Instead of only training "real vs. fake" (binary classification), the model is also trained to guess **which specific forgery technique** created the fake (face-swap? face-reenactment? synthetic face?) — a multi-class classification task. This forces the model to learn fine, technique-specific artifact patterns instead of one vague "something's off" signal. There are three branches inside each DFF-Adapter block:
- **Authenticity branch** — does the real/fake job (the branch we actually care about)
- **Forgery-type branch** — auxiliary task, classifies which manipulation method was used (training scaffolding only — discarded at inference time)
- **Shared branch** — a bridge that lets fine-grained knowledge learned by the forgery-type branch flow into and help the authenticity branch too

**Step E — Use a "mixture of experts" style router for smarter feature usage (this is the paper's third key idea).**
Within each DFF-Adapter, instead of one single LoRA module handling everything, there's a **pool of N LoRA "experts"** (small specialist modules). The input features get split into **h sub-space "heads"** (chunks along the channel dimension). For each chunk, a small **router** network scores all N experts and picks the **top-3** best-fit ones, combining their outputs. Intuition: different forgery types leave different "flavors" of artifacts, so letting different feature sub-spaces specialize via different expert combinations captures more diverse patterns than one-size-fits-all.

**Step F — Train with two forward passes per batch.**
For every batch of images, the frozen DINOv2 + adapters are run **twice**:
1. Task-flag = 0 → authenticity mode → binary cross-entropy loss (L_bce) — "is this real or fake?"
2. Task-flag = 1 → forgery-type mode → multi-class cross-entropy loss (L_ftc) — "which technique made this fake?"

Total loss = λ₀·L_bce + λ₁·L_ftc (λ values are just weights controlling how much each task matters — paper uses λ₀=10, λ₁=2). Only the adapters + tiny classifier heads get updated via backpropagation — DINOv2 itself never changes.

**Step G — At inference (actual use), drop the forgery-type branch.**
Once training is done, only the authenticity branch + shared branch are used to make the real/fake decision. The forgery-type branch was just a training aid.

## 1.4 How success is measured

- **Intra-dataset test:** train and test on the same dataset (FF++) — tests basic competence.
- **Cross-dataset test:** train on FF++, test on entirely different datasets (Celeb-DF-v2, DFDCP) — tests generalization to new data.
- **Metric — AUC (Area Under the ROC Curve):** a number from 50 (random guessing) to 100 (perfect separation of real vs. fake) measuring how well the model ranks fakes as "more fake" than reals across all possible decision thresholds.
- **Metric — EER (Equal Error Rate):** the point where the false-accept rate equals the false-reject rate; lower is better.

## 1.5 The paper's own admitted limitation (Appendix D) — and our extension

The paper's Appendix D states: the forgery-type auxiliary task assumes different manipulation techniques leave **consistent, distinguishable** artifact patterns. In reality, artifacts can overlap between techniques, be subtle, or not fit cleanly into any known category — which can inject **noisy training signal** into the auxiliary task, potentially hurting the main authenticity task.

**Our extension:** instead of forcing a hard, always-confident forgery-type label, we apply **label smoothing** to the forgery-type targets (softening the one-hot target distribution slightly) and compare cross-dataset AUC/EER against the paper's original hard-label version. An optional stretch goal (only if time allows): an explicit "ambiguous/unknown" class for uncertain samples.

### CHECKPOINT 8 — LoRA Expert Bank (dummy-tensor stage)
**Owner:** M2 primary
**What:** Before touching real DINOv2 features, implement the LoRA expert bank concept on dummy/random tensors: a pool of N LoRA modules (A_j, B_j pairs), where given an input feature slice, you can compute all N experts' outputs.
**Why:** Isolates and de-risks the hardest new code (the router/expert logic) from the complexity of the real model, so bugs are easier to find. Building on dummy tensors lets you unit-test shapes and logic in isolation.
**Done when:** Given a random input tensor of the right shape, you can compute outputs from all N experts and verify output shapes match expectations, with unit tests.

### CHECKPOINT 9 — Forgery-Aware Multi-Head Router (dummy-tensor stage)
**Owner:** M2 primary
**What:** Implement the router: split a feature tensor into h sub-space heads, for each head compute a softmax score over the N experts, select the top-3, normalize their weights (renormalize the top-3 softmax scores to sum to 1), compute the weighted combination of the top-3 experts' outputs for that head, then concatenate all heads' outputs back together.
**Done when:** On dummy tensors, you can verify: (a) exactly 3 experts are selected per head, (b) the selection can differ across heads and across different input tensors (i.e., it's actually adaptive, not always picking the same 3), (c) output shapes are correct after concatenation.
